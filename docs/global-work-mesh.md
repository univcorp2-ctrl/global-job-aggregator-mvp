# Global Work Mesh — Production world-wide opportunities platform

Production: https://global-work-mesh.pages.dev/

## What has actually shipped (2026-10-28)
- Public, responsive job search portal, mobile/tablet optimized: source/title/company/region filters, AI-first discovery filter, recency/title sorting, provider-native application links, AI proposal prompt copy.
- Real, attributed API data from two providers currently authorized for redistribution on our own site: Himalayas and Jobicy. First deploy: 50 records (Himalayas 20, Jobicy 30), two heuristic AI-first *candidates*. No private job postings or Upwork/Contra scraped content.
- Public JSON data generated by `scripts/global_work_mesh.py` from the existing private Google Drive SQLite, with strict source allowlist and sensitive-field minimization, and manually verified production HTTP 200 HTML/JSON. Updated by Windows task RevenueAgent-GlobalWorkMesh-Publish every 6 hours after collection, hidden pythonw, initial task execution returned exit 0 and published successfully.
- The separate agent engine's `app/revenue_policy.py` makes paid digital-deliverable triage conservative. It rejects mere `freelance` job titles as proof of AI-deliverable project. Outsource-worker searching requires **all** of a real awarded provider contract id, client written consent, platform permission, funded scope, and an actual AI failure. It never authorizes spending even when all true.
- Python tests and Node syntax checked on authorized PC. 65 passing tests as of deployment.

## Market access / limitations
- Himalayas: cite their original source, preserve API `applicationLink` as the Apply destination, no syndicated third-party feeds or schema JobPosting republishing, remove closed listings from regular refresh.
- Jobicy: link to the canonical jobicy.com listing, attribution, normal caching and API limits.
- Upwork: accessible in ChatGPT only via existing official MCP OAuth; the Web portal does NOT share or use its credentials. Upwork native proposal preview/Connects/Dispute Assistance acceptance are provider-owned and cannot be bypassed.
- Contra: official MCP supports drafting but requires prepare/confirm and onboarding prerequisites; no independent background OAuth broker yet.
- Freelancer.com: Web login is not a scoped production API token and its published User Agreement limits bots/API calls without written permission; automated bidding is **not enabled**.
- Apify: catalog metadata read-only, not an automatic sales system. An existing private actor has been built, but no verified paying customers.
- The 50 displayed items are primarily remote employment positions; **they are not 50 paid freelance contracts**. AI-first indicator is a non-binding prefilter and does not guarantee that AI-only delivery meets the buyer's expectations.
- No cross-platform DMs, contract signatures, escrow, payment authorization, supplier purchases, or user identity verification from this public site.
- Zero confirmed signed contracts and zero paid revenue as of publishing.

## Ops
```bash
python -m pytest -q
node --check web/global-work-mesh/app.js
python scripts/global_work_mesh.py --root "<private Google Drive folder>" --deploy
```
Private files remain under the user's Google Drive's 00.Revenue_Agent directory. Cloudflare Pages project: `global-work-mesh`. Publish only five allowlisted assets including `jobs.json`. The public site's UI polls its own static JSON (refreshing a page does not force an API sync). For real automation of proposals or conversations, obtain authorized provider OAuth/write scopes and comply with their confirmation semantics; do not use scraped browser sessions or hidden cookie replay.
